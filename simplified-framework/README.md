# 綦桐AI网关·轻量跨平台对话框架（简化版）

一套平台中立的 AI 对话 Agent 框架骨架：把「收消息 → 过滤/限流 → 智能体思考 → 调用工具 → 回复」的通用链路抽象成可插拔模块，**核心逻辑只写一遍，平台差异交给适配器**。

## 设计思路（架构要点）

1. **平台中立**：所有平台（QQ/微信/网页/控制台）统一转成 `Message` 模型，适配器只做「收→Message」「Message→发」两件事，核心零感知平台差异。
2. **责任链管道**：消息处理拆成一串独立 Stage（白名单→限流→Agent→回复），每个 Stage 可插拔、可调优先级；加新能力 = 加一个 Stage，不污染核心。
3. **统一模型接口**：模型服务层只依赖 `Provider.chat()` 接口，换厂商/换模型 = 换实现类，核心不动。
4. **Agent 工具循环**：模型输出工具调用块 → 解析 → 注册表执行 → 结果回填 → 再调模型 → 直到不再调用为止（带最大轮数护栏 + 权限拦截 + 异常隔离）。
5. **事件驱动解耦**：模块间不直接引用，发事件/挂监听；插件 = 注册事件监听，动态扩展零侵入。

## 目录

```
simplified-framework/
├── core/          核心：统一消息模型 / 事件总线 / 责任链管道 / 内置Stages / 配置
├── provider/      模型服务层：统一 LLM 接口 + 回显/HTTP 实现
├── agent/         智能体层：工具注册表 + Agent 循环
├── platform/      平台适配层：控制台/Webhook 示例
├── plugins/       插件层：事件钩子示例
├── demo.py        控制台交互演示
└── selftest.py    全链路自测
```

## 运行

```bash
# 自测（验证全链路）
python3 selftest.py

# 控制台交互演示
python3 demo.py
```

## 如何扩展

- **加一个工具**：注册进 `ToolRegistry`（`Tool(name, func, desc)`），模型即可调用。
- **加一个平台**：继承 `BasePlatform` 实现 incoming/send，注册到平台注册表。
- **加一个处理关卡**：继承 `Stage` 实现 handle，注册进 Pipeline。
- **加一个插件**：在插件模块导出 install(bus)，框架加载时自动挂事件监听。

> 本例仅作架构演示；生产级能力（多轮记忆持久化、并发调度、流式、鉴权、故障转移）可参考网关主项目对接补齐。
